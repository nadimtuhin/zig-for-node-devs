Appendix 12 • Quick Reference

JavaScript to Zig Rosetta Stone Cheatsheet

Direct mapping between familiar JavaScript / TypeScript patterns and their idiomatic Zig equivalents: types, collections, control flow, errors, and V8 heap memory versus Zig allocators.

Direct Answer

Most JavaScript constructs have a direct Zig counterpart. TypeScript number becomes a sized type such as i32, usize or f64, string becomes the byte slice []const u8, boolean becomes bool, and null becomes an optional ?T. Array becomes a slice []T or std.ArrayList(T), Map becomes std.StringHashMap (string keys) or std.AutoHashMap (integer keys), Set becomes either map with void values, throw becomes return error.Name, try/catch becomes try and catch |err|, and finally becomes defer. Where V8 allocates and garbage-collects for you, Zig asks an allocator: allocator.create(T) replaces new, and you free it yourself. Snippets target Zig 0.14.

How Do TypeScript Types Map to Zig Types?

Every TypeScript primitive has a Zig type, but Zig types state their size: pick an integer width (u8, i32, usize) or a float (f64) instead of one number, use []const u8 for strings, and wrap a type in ?T when it can be absent.

Declarations and primitive types

TypeScript declarations and primitive types mapped to Zig
JavaScript / TypeScript Zig Equivalent Key Difference
const x = 10; / let y = 20; const x: i32 = 10; / var y: i32 = 20; Explicit integer bit widths (u8, i32, usize). A var that is never mutated is a compile error.
number i32 / i64 / usize / f64 You choose signedness and width; there is no single double-precision number. Use usize for lengths and indexes, f64 for JavaScript-style floating point. Integer overflow panics in Debug and ReleaseSafe.
string []const u8 A slice of UTF-8 bytes (pointer plus length), not a string object. A literal like "hi" has type *const [2:0]u8 and coerces to []const u8.
boolean bool No truthiness: if (count) does not compile for an integer, write if (count != 0).
null / undefined ?T set to null Absence is null in an optional type. Zig's undefined means uninitialized memory, not a value.
any anytype parameter, or *anyopaque pointer Neither turns type checking off. anytype makes a function generic and is checked per call at compile time; *anyopaque is a type-erased pointer you cast back with @ptrCast and @alignCast.
BigInt u128 / i128, or std.math.big.int Fixed wide integers cover many cases; arbitrary precision needs an allocator.
type Point = { x: number; y: number } const Point = struct { x: f64, y: f64 }; A type is a compile-time value bound with const; fields have a fixed memory layout.
type Shape = Circle | Square (discriminated union) const Shape = union(enum) { circle: Circle, square: Square }; A tagged union; switch on it must handle every tag.
typeof x @TypeOf(x) Resolved at compile time, not at runtime.
a === b a == b / std.mem.eql(u8, a, b) == works on numbers; compare strings and slices by content with std.mem.eql.

How Do Functions and Control Flow Map to Zig?

Zig control flow reads like JavaScript with fewer operators: if and switch are expressions, for captures items between pipes, and there is no async/await, so I/O is synchronous or moved onto threads.

Functions, loops, and branching

JavaScript functions and control flow mapped to Zig
JavaScript / TypeScript Zig Equivalent Key Difference
function add(a, b) { return a + b; } fn add(a: i32, b: i32) i32 { return a + b; } Parameter and return types are required; parameters are immutable.
Closures / arrow functions A struct holding the context plus a method, or a function pointer plus an explicit context argument Zig has no capturing closures; captured state is passed explicitly.
Default parameters, { a, b } options object An options struct with field defaults: fn run(opts: Options) No default arguments; struct field defaults fill the same role.
cond ? a : b if (cond) a else b if is an expression; there is no ?: operator.
for (const item of items) for (items) |item| { ... } / for (items, 0..) |item, i| The capture goes between pipes; the index range is an explicit second operand.
while (i < n) { i++; } while (i < n) : (i += 1) { ... } The continue expression after : runs on every iteration; there is no ++ operator.
switch (x) { case 1: ... default: ... } switch (x) { 1 => ..., else => ... } An expression with no fall-through that must cover every value.
async / await A plain blocking call, or std.Thread.spawn / std.Thread.Pool Zig 0.14 has no async/await and no built-in event loop. Calls block until done; run work in parallel on threads and join() them.
Promise.all([a(), b()]) const t = try std.Thread.spawn(.{}, a, .{}); then b(); and t.join(); Real OS threads sharing memory, so shared state needs std.Thread.Mutex or atomics. The thread function can only return void, !void, u8, or noreturn, and join() hands nothing back, so pass a result pointer in the args tuple to get a value back.

How Do Errors and Optionals Map to Zig?

Zig has no exceptions. A function that can fail returns an error union !T; try passes the error to the caller (like re-throwing), catch |err| handles it in place, and defer does the job of finally.

Exceptions become error unions, null checks become optionals

JavaScript exceptions and null handling mapped to Zig
JavaScript / TypeScript Zig Equivalent Key Difference
throw new Error("msg") return error.InvalidInput; An error is a named value from an error set, returned inside an error union !T. It carries no message; Debug builds record an error return trace separately.
try { ... } catch (e) { ... } val catch |err| fallback; Handles the error value inline as an expression; nothing unwinds the stack.
catch (e) { if (e instanceof NotFound) ... } catch |err| switch (err) { error.NotFound => ..., else => return err } Error sets are known at compile time, so switch can check that every error is handled.
Re-throwing to the caller const v = try mayFail(); try returns the error to the caller, so the caller's return type must include an error set.
finally { cleanup(); } defer cleanup(); Declared right next to resource acquisition and run when the scope exits. errdefer runs only on error returns.
val ?? defaultValue maybe_val orelse defaultValue Unwraps an optional ?T or supplies the default.
a?.b if (a) |v| v.b else null No ?. operator; unwrap with an if capture.
value! (TS non-null assertion) maybe_val.? Asserts non-null; on null it panics in safe build modes instead of silently continuing.

How Do Collections and Strings Map to Zig?

Fixed data lives in arrays and is passed around as slices ([]T). Anything that grows, like Array.push, Map or Set, is a standard-library container that takes an allocator and must be freed with deinit().

Arrays, maps, sets, and objects

JavaScript arrays, maps, sets, and objects mapped to Zig
JavaScript / TypeScript Zig Equivalent Key Difference
Array<T> / T[] []T / []const T slice, or std.ArrayList(T) when it grows A slice is a view (pointer plus length) over memory someone else owns; an ArrayList owns a growable buffer.
[1, 2, 3] (fixed) const a = [_]i32{ 1, 2, 3 }; An array has a compile-time length; pass it around as a slice []const i32.
arr.length arr.len Out-of-bounds indexing panics in Debug and ReleaseSafe.
const list = [] / list.push(item) var list = std.ArrayList(i32).init(allocator); / try list.append(item); Needs an allocator and defer list.deinit(); append may return error.OutOfMemory. Zig 0.15 makes the unmanaged form the default.
arr.slice(1, 3) arr[1..3] Slicing copies nothing: the result points into the same memory.
new Map() std.StringHashMap(V).init(allocator) Explicit allocator and deinit(). The map does not copy string keys, so keep them alive. map.get(k) returns ?V.
Map<K, V> with integer keys std.AutoHashMap(K, V) Hashes integer, enum, and pointer keys, and structs made of them. Slice and float keys are a compile error: use StringHashMap for []const u8 keys.
Set<T> std.AutoHashMap(T, void) A map with a zero-size void value: try set.put(x, {}) and set.contains(x). Use std.StringHashMap(void) for strings.
{ name: "a", age: 3 } const p = Person{ .name = "a", .age = 3 }; A struct with fixed, typed fields declared up front; no adding fields at runtime.
JSON.parse(text) try std.json.parseFromSlice(T, allocator, text, .{}) Parses into a typed struct T; call .deinit() on the returned result.

Strings and output

JavaScript string methods and console output mapped to Zig
JavaScript / TypeScript Zig Equivalent Key Difference
str.length str.len Counts UTF-8 bytes, not UTF-16 code units or characters.
console.log(`x=${x}`) std.debug.print("x={d}\n", .{x}); Format string plus an argument tuple, checked at compile time. print writes to stderr.
Template string that builds a value try std.fmt.allocPrint(allocator, "x={d}", .{x}) Allocates the result, so you must free it.
s.split(",") std.mem.splitScalar(u8, s, ',') Returns a lazy iterator (call .next()), not an array. Use splitSequence for multi-byte separators; the old unsuffixed std.mem.split is deprecated in 0.13 and a compile error in 0.14.
s.includes("ab") / s.startsWith("ab") std.mem.indexOf(u8, s, "ab") != null / std.mem.startsWith(u8, s, "ab") Free functions over byte slices rather than methods on a string object.
s.trim() std.mem.trim(u8, s, " \t\r\n") You list the bytes to trim; the result is a view into the same memory, not a copy.
parseInt(s, 10) try std.fmt.parseInt(i32, s, 10) Returns an error on bad input instead of NaN.

How Does V8 Memory Compare to Zig Allocators?

In V8, new allocates on a garbage-collected heap and the collector frees it later. In Zig, you ask an std.mem.Allocator for memory (allocator.create(T) for one value, allocator.alloc(T, n) for many) and free it yourself, usually with defer on the next line.

Allocation, ownership, and cleanup

V8 heap allocation and garbage collection mapped to Zig allocators
JavaScript / V8 Zig Equivalent Key Difference
new Foo() / new Object() const p = try allocator.create(Foo); + defer allocator.destroy(p); Returns a *Foo whose fields are uninitialized until you set them, for example p.* = .{ ... }. Nothing frees it for you.
new Array(n) / Buffer.alloc(n) const buf = try allocator.alloc(T, n); + defer allocator.free(buf); Returns a slice []T with undefined contents; unlike Buffer.alloc it is not zero-filled, so @memset(buf, 0) if you need zeros.
[...arr] try allocator.dupe(T, items) A shallow copy of a slice into new memory that the caller now owns and must free. Pointers inside the items are shared, not cloned.
Garbage collection Explicit free / destroy, scheduled with defer and errdefer No collector and no pauses; the cost is that ownership is your job. Functions that allocate take an Allocator parameter, so the cost shows in the signature.
Short-lived objects per request (V8 young generation) std.heap.ArenaAllocator Allocate freely while handling the request, then arena.deinit() frees everything at once.
Local variables Stack values: var buf: [256]u8 = undefined;, optionally wrapped in std.heap.FixedBufferAllocator Stack memory dies with the function, so returning a pointer or slice to it is a dangling-pointer bug.
Heap snapshots / --inspect leak hunting std.heap.DebugAllocator (GeneralPurposeAllocator in Zig 0.13), or std.testing.allocator in tests Reports leaked allocations with stack traces when it is deinitialized, and catches double frees.

How Do Modules and Tooling Map to Zig?

The zig binary replaces node, npm, and your bundler: zig run compiles and runs a file, zig build runs a build.zig script, and zig fetch --save adds a dependency.

Imports and npm-style commands

JavaScript modules and npm commands mapped to Zig tooling
JavaScript / TypeScript Zig Equivalent Key Difference
import { x } from "./m.js" const m = @import("m.zig"); Imports a whole file as a struct; pub marks what is exported.
console.assert(cond) std.debug.assert(cond); Unreachable (undefined behavior) when false in ReleaseFast, so use it for invariants, not input validation.
node file.js zig run file.zig Compiles then runs; there is no interpreter.
npm test zig test file.zig / zig build test test "name" { ... } blocks live next to the code.
npm run build / package.json scripts zig build with build.zig The build graph is Zig code. -Doptimize=ReleaseSafe and -Dtarget=... are the common flags.
npm install pkg zig fetch --save <url> Dependencies are URLs with content hashes in build.zig.zon; there is no central registry.
