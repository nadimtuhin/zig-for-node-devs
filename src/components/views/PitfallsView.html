Appendix 09 • Guardrails

Top 8 Known Pitfalls & Footguns

Where JavaScript and Node.js intuition leads to bugs in systems programming.

1. Returning a Slice of a Local Stack Array

In Node.js, returning an array from a function safely retains it in heap memory via garbage collection. In Zig, returning &stack_buf results in a dangling pointer once the stack frame unwinds. Always allocate slices from a caller-passed allocator when returning dynamically sized data.

2. Reading `undefined` Memory

In JS, undefined is a concrete value of type undefined. In Zig, var x: i32 = undefined; means the variable contains whatever garbage bytes were previously at that memory location. Reading it before writing is illegal and triggers panics in Debug mode.

3. Forgetting `defer allocator.free(slice)`

Because there is no garbage collector, every heap allocation through an allocator that is not an Arena will leak if not paired with a corresponding free or deinit. Use std.testing.allocator to automatically detect memory leaks during testing.

4. Modifying Function Parameters Directly

All function parameters in Zig are strictly immutable const values. Writing param = new_value; fails at compile time. Make an explicit local copy var local = param; or pass a mutable pointer *T.
