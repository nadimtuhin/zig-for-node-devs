Appendix 03 • Native Integration

C Interop & True Node-API Addons

Building Node-API addons with Zig's bundled C compiler instead of node-gyp, Python, and a system C++ toolchain.

Direct Answer

Zig bundles Clang (zig cc / zig c++) and libc support, and imports C headers with @cImport and @cInclude. A Node.js native addon is a shared library that exports napi_register_module_v1: build it with b.addSharedLibrary, add the node_api.h include path, set linker_allow_shlib_undefined = true, install it as addon.node, and load it with require('./addon.node'). That removes node-gyp, Python, and a system C toolchain, but not the Node-API headers.

  • The headers come from Node's include/node directory or the node-api-headers npm package.
  • Windows additionally needs the node.lib import library.
  • Node-API is ABI-stable, so one build works across Node versions that support the same Node-API version.

Why can Zig replace node-gyp for native addons?

Building native C++ addons for Node.js with node-gyp typically requires Python, make or Visual Studio build tools, and a working C++ compiler. A toolchain mismatch on one machine is a common cause of failed npm install.

Zig ships Clang as zig cc and zig c++, plus libc headers and sources for musl, glibc (selectable versions such as -target x86_64-linux-gnu.2.28), and mingw-w64, and libSystem stubs for macOS. Cross-compiling C for those targets needs no extra sysroot. @cImport translates headers through translate-c, so no hand-written wrapper is needed.

# use Zig as a drop-in C compiler, even cross-compiling zig cc -target aarch64-linux-musl -O2 hello.c -o hello

How do I call C from Zig with @cImport?

Import C headers directly into Zig. Zig translates C types, pointers, and struct layouts. Linking libc is required for libc headers (linkLibC() in build.zig, or -lc on the command line):

c_interop.zig Zig 
const std = @import("std");

// Import standard C headers directly
const c = @cImport({
    @cInclude("stdio.h");
    @cInclude("math.h");
});

pub fn main() void {
    // 1. Call standard C math functions
    const result = c.sqrt(144.0);
    std.debug.print("Square root from C math.h: {d}\n", .{result}); // 12

    // 2. Interacting with C strings: converting [*:0]const u8 to Zig slice []const u8
    const c_str: [*:0]const u8 = "Hello from C string";
    const zig_slice: []const u8 = std.mem.span(c_str);
    std.debug.print("Zig slice length: {d}, content: {s}\n", .{ zig_slice.len, zig_slice });
}

Note: in 0.14 @cImport is a builtin. Newer Zig versions move header translation into the build system (addTranslateC), so expect this to change after 0.14.

How do I compile C source files alongside Zig?

Add C files to the same artifact with addCSourceFiles (or addCSourceFile for one file) and link libc. Zig compiles them with its bundled Clang, using the same -Dtarget:

build.zig (excerpt, Zig 0.14) Zig 
exe.addCSourceFiles(.{
    .files = &.{ "vendor/sqlite3.c" },
    .flags = &.{ "-std=c99" },
});
exe.addIncludePath(b.path("vendor"));
exe.linkLibC();

How do I build a Node-API (.node) addon in Zig?

A .node file is a shared library that Node loads with dlopen (or LoadLibrary) and then asks for the symbol napi_register_module_v1. The Node-API functions it calls (napi_create_function and so on) are not linked in: the node binary provides them when the addon loads. That is why the build must allow undefined symbols.

Step 1: get the Node-API headers

You still need node_api.h and js_native_api.h. Either use the include/node directory of your Node installation, or install the node-api-headers package, which this example assumes:

npm install --save-dev node-api-headers

Step 2: write the build.zig

build.zig (Node-API addon, Zig 0.14) Zig 
const std = @import("std");

pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});

    // works in 0.13/0.14 (deprecated in 0.14); prefer b.addLibrary(.{ .linkage = .dynamic, ... }) on 0.14+
    const lib = b.addSharedLibrary(.{
        .name = "addon",
        .root_source_file = b.path("addon.zig"),
        .target = target,
        .optimize = optimize,
    });
    lib.linkLibC();

    // Header include path (node-api-headers package; or Node's include/node directory)
    lib.addIncludePath(b.path("node_modules/node-api-headers/include"));

    // napi_* symbols are resolved by the node binary at load time
    lib.linker_allow_shlib_undefined = true;

    // Install as zig-out/lib/addon.node
    const install = b.addInstallArtifact(lib, .{ .dest_sub_path = "addon.node" });
    b.getInstallStep().dependOn(&install.step);
}

Windows caveat: the Windows linker needs an import library so it knows which symbols come from node.exe. You must supply node.lib (distributed with Node's headers/dev files) and link it. This guide has not verified a complete Windows recipe, and on macOS the dynamic-lookup behavior of the linker may need additional flags; test on each platform you ship.

Step 3: write addon.zig

addon.zig (Native Node-API Addon) Zig 
const std = @import("std");

// Import Node-API C declarations (needs the include path from build.zig)
const napi = @cImport({
    @cInclude("node_api.h");
});

// Implementation of the exported function: multiply(a, b)
fn multiply(env: napi.napi_env, info: napi.napi_callback_info) callconv(.c) napi.napi_value {
    var argc: usize = 2;
    var argv: [2]napi.napi_value = undefined;
    _ = napi.napi_get_cb_info(env, info, &argc, &argv, null, null);

    var a: f64 = 0;
    var b: f64 = 0;
    _ = napi.napi_get_value_double(env, argv[0], &a);
    _ = napi.napi_get_value_double(env, argv[1], &b);

    var result: napi.napi_value = undefined;
    _ = napi.napi_create_double(env, a * b, &result);
    return result;
}

// Node looks up this exact symbol when it loads the .node file
export fn napi_register_module_v1(env: napi.napi_env, exports: napi.napi_value) napi.napi_value {
    var fn_val: napi.napi_value = undefined;
    _ = napi.napi_create_function(env, "multiply", std.math.maxInt(usize), multiply, null, &fn_val);
    _ = napi.napi_set_named_property(env, exports, "multiply", fn_val);
    return exports;
}

This sketch ignores the napi_status return values for brevity; real addons should check them and throw a JavaScript error on failure. std.math.maxInt(usize) is the value of NAPI_AUTO_LENGTH (length computed from the NUL terminator). Zig 0.14 spells it callconv(.c); .C is a deprecated alias there and the only spelling in 0.13.

How do I load the addon from JavaScript?

Build, copy the output next to your script, and require it. Target a different platform with -Dtarget, as long as you have that platform's headers:

# no node-gyp, no Python, no system C toolchain (headers still required) zig build -Doptimize=ReleaseFast cp zig-out/lib/addon.node ./addon.node
index.js (Consuming in Node.js) JavaScript 
// CommonJS: require works directly. In an ES module, use createRequire(import.meta.url).
const addon = require('./addon.node');

console.log(addon.multiply(6.5, 4.0)); // 26

Each call crosses the JS/native boundary, which has a cost. A native addon pays off for substantial computation, not for trivial arithmetic like this demo; measure before adopting it.

Can I skip Node-API headers with Bun FFI?

If you use Bun, you can export a plain C-ABI function from Zig (export fn multiply(a: f64, b: f64) f64, built as a shared library) and call it via bun:ffi without any Node-API headers:

import { dlopen, FFIType } from "bun:ffi";

const { symbols: { multiply } } = dlopen("./libaddon.so", {
  multiply: {
    args: [FFIType.f64, FFIType.f64],
    returns: FFIType.f64,
  },
});

console.log(multiply(10.5, 2.0)); // 21
