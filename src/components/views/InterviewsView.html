Appendix 11 • Senior Interview Q&A

Senior Systems Interview Q&A for Zig

High-frequency architectural questions asked in senior systems and performance engineering interviews.

Q1: Why does Zig pass an explicit Allocator to functions rather than using a global malloc?

Answer: Passing allocators explicitly eliminates hidden control flow and hidden side effects. It allows callers to determine memory lifecycles based on usage patterns: an HTTP request handler can pass a fast ArenaAllocator that deallocates all allocations at once upon request completion, while a unit test passes std.testing.allocator to detect leaks. Functions that take no allocator are mathematically guaranteed never to allocate heap memory.

Q2: How does `comptime` achieve generics without C++ template bloat or runtime type erasure?

Answer: In Zig, types are first-class values at compile time. A generic struct is simply a regular function that accepts a comptime T: type parameter and returns a type. The compiler executes normal Zig code during compile time to construct the struct layout. There is no special template metaprogramming language to learn, compile times remain rapid, and the resulting machine code has zero runtime reflection overhead.

Q3: How are optional pointers `?*T` represented in memory under the hood?

Answer: Zig optimizes optional pointers with zero space overhead using pointer tagging. Because a valid pointer in modern operating systems cannot be null (address 0), Zig represents null as the null pointer value 0x0. Therefore, ?*T occupies exactly 8 bytes on a 64-bit architecture (the same as a raw pointer), avoiding any extra boolean discriminant flag.

Q4: What is the mechanical difference between an Array `[N]T` and a Slice `[]T`?

Answer: An array [N]T has a fixed length known at compile time, and its values reside directly in place (e.g. on the stack or inline in a struct). A slice []T is a 16-byte fat pointer consisting of a pointer to the first element ([*]T) and a runtime length (usize). Slices do not own memory; they represent a view over contiguous elements with runtime bounds checking in Debug and ReleaseSafe modes.
